# Problemas conhecidos e contornos de bibliotecas

<uso>
- Registro contínuo de travas já investigadas no **Sherlock AI** (`split-ai`): comportamento de biblioteca externa ou do runtime (TypeORM, NestJS, Fastify, Jest, LangChain/LangGraph, Voyage AI, `bun`), contorno aplicado, atalho adotado ou problema sem solução.
- Antes de investigar qualquer erro inesperado, falha de compilação/boot ou limitação de biblioteca, procure aqui. Para consultar ou registrar uma nova entrada, use a skill `problema-conhecido` (`.agents/skills/problema-conhecido/SKILL.md`).
- Regra de arquitetura não mora apenas aqui: ela mora no arquivo de regra dono (`.agents/rules/NN-*.md`), e a entrada `PC-NNN` registra a trava e referencia a regra dona.
</uso>

## Ordem de contorno

<tabela>

| #   | Estratégia                                                                                  | Quando usar                                                                                      |
| --- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1   | Configuração ou opção pública da biblioteca                                                 | Sempre a primeira tentativa.                                                                     |
| 2   | Composição no adaptador/provider (`src/infrastructure/providers/`) ou ponto único de uso    | A biblioteca não cobre o caso diretamente, mas expõe o necessário para contorná-lo na fronteira. |
| 3   | Ponto de extensão oficial da biblioteca (callback, custom loader, strategy, module factory) | O gap está dentro do fluxo da biblioteca e ela oferece extensão tipada.                          |
| 4   | Atalho isolado (`as unknown as`, `ts-node`, DDL idempotente) documentado aqui               | Incompatibilidade de tipagem CJS/ESM ou limitação estrutural sem solução limpa.                  |
| 5   | Registrar como `sem-solucao` com a alternativa operacional adotada                          | Nenhuma das anteriores é viável sem custo desproporcional ou depende de terceiro.                |

</tabela>

### PC-020 — `SyntaxError: Unexpected token 'export'` com dependência aninhada de `cookie` no Jest

| Campo                  | Valor                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Status                 | contornado                                                                                                                                                                                 |
| Biblioteca             | `cookie@2.0.1` (transitiva via `light-my-request` / Fastify), `ts-jest@29.4.6`                                                                                                             |
| Sintoma                | Execuções do Jest (`auth-layer.spec.ts`, `http-layer.spec.ts`) falham com `SyntaxError: Unexpected token 'export'` em `cookie/dist/index.js` ao chamar `app.inject()`.                     |
| Causa                  | A versão 2 de `cookie` é pacote ESM puro (`"type": "module"`). O Jest ignora `node_modules` na transformação padrão do `ts-jest`, enquanto a versão raiz instalada é CJS (`cookie@1.1.1`). |
| Solução                | Mapear `^cookie$` no `moduleNameMapper` do `package.json` e `test/jest-e2e.json` apontando para a compilação CommonJS raiz (`<rootDir>/../node_modules/cookie/dist/index.js`).             |
| Onde                   | `package.json`, `test/jest-e2e.json`                                                                                                                                                       |
| Regra dona             | `.agents/rules/11-testes.md`                                                                                                                                                               |
| Tentativas descartadas | —                                                                                                                                                                                          |
| Remover quando         | Jest for configurado para transformar ESM nativo ou dependências transitivas padronizarem resolução CJS.                                                                                   |
| Registrado em          | 2026-10-28                                                                                                                                                                                 |
